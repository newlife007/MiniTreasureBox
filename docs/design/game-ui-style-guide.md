# MiniTreasureBox 小游戏 UI 设计规范

## 1. 文档目的

本文档定义 MiniTreasureBox 小游戏页面的统一视觉语言、布局结构、交互状态和实现约束，用于：

- 保持现有五款游戏的界面一致性。
- 指导后续新增小游戏的 UI 设计和实现。
- 避免游戏页面退化为临时表单或孤立画布。
- 保证浅色主题、深色主题、键盘操作和辅助功能可用。

本规范描述当前实现。主要代码来源：

- `src/domain/games/ui/game_page_shell.*`
- `src/domain/games/ui/game_canvas.*`
- `src/domain/games/ui/game_visual_theme.*`
- `src/domain/games/ui/board_geometry.h`
- `src/domain/games/game_widgets.cpp`
- `src/app/main_window.cpp`

## 2. 设计定位

小游戏采用“现代桌面工具风格 + 克制的街机感”。视觉应轻松、有辨识度，但不能使用过度卡通化、强闪烁或高饱和的大面积装饰。

### 2.1 设计原则

1. **游戏内容优先**：棋盘或主操作区是页面视觉中心。
2. **结构统一**：所有游戏使用相同的信息栏、配置栏、舞台、说明栏和控制栏。
3. **个性适度**：每款游戏使用独立强调色，页面结构和基础控件保持一致。
4. **状态明确**：暂停、胜利、失败和和棋必须直接显示在画布上。
5. **操作连续**：视觉反馈和动画不能阻塞键盘连续输入。
6. **本地优先**：统计、设置和背景音乐状态只保存在本机。
7. **跨主题可读**：颜色从 `QPalette` 派生，不能假设固定的白色背景。

## 3. 页面信息架构

所有小游戏使用统一的 `GamePageShell`：

```text
┌──────────────────────────────────────────────────────────────┐
│ 状态卡                   当前指标             最佳指标       │
│ ● 状态                   240 分               1,860 分       │
├──────────────────────────────────────────────────────────────┤
│ [模式 ▼] [难度/范围 ▼]                    本局目标           │
├──────────────────────────────────────────────────────────────┤
│                                                ┌───────────┐ │
│          ┌──────────────────────────┐          │ 操作说明  │ │
│          │                          │          │ 快捷键    │ │
│          │        游戏舞台          │          │           │ │
│          │                          │          │ 本地统计  │ │
│          └──────────────────────────┘          └───────────┘ │
├──────────────────────────────────────────────────────────────┤
│ [暂停/继续] [重新开始] [游戏专用操作]         □ 背景音乐    │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 垂直顺序

页面从上到下固定为：

1. 信息栏 `information`
2. 配置栏 `gameConfigBar`
3. 游戏工作区 `workspace`
4. 控制栏 `gameControlBar`

页面根布局：

- 外边距：`0`
- 垂直间距：`12 px`
- 工作区使用剩余空间

### 3.2 工作区

工作区由游戏舞台和说明栏组成：

- 游戏舞台使用伸缩宽度。
- 说明栏宽度为 `168–205 px`。
- 舞台与说明栏间距为 `14 px`。
- 默认窗口下，应优先保证舞台不小于 `280 × 280 px`。

## 4. 通用组件规范

## 4.1 状态卡

对象名：

- `gameStateCard`
- `gameStateCaption`
- `gameStatus`

规范：

- 状态卡占据信息栏剩余宽度。
- 左侧使用对应游戏的 `3 px` 强调色边框。
- 标题使用弱化文字，当前状态使用 `15 px` 粗体。
- 状态文案应短且可立即理解，例如“游戏中”“已暂停”“电脑思考中…”。

## 4.2 指标卡

对象名：

- `gameMetricCard`
- `gameMetricTitle`
- `scoreLabel`
- `highScoreLabel`

规范：

- 内边距：水平 `14 px`，垂直 `9 px`。
- 标题使用 `11 px` 弱化文字。
- 数值使用 `18 px` 粗体。
- “当前”可以表示分数、尝试次数、当前行棋方或等级。
- “最佳”可以表示最高分、最佳步数或本地胜局。

## 4.3 配置栏

对象名：

- `gameConfigBar`
- `gameOptionLabel`
- `gameGoal`

规范：

- 内边距：水平 `12 px`，垂直 `8 px`。
- 控件间距：`8 px`。
- 模式和难度选择放在左侧。
- 本局目标放在右侧，使用应用主色和半粗体。
- 修改配置后开始新一局，不在旧棋局中途混用新规则。

## 4.4 操作说明与统计

对象名：

- `gameHelpCard`
- `gameHelpTitle`
- `gameInstructions`
- `gameStats`

规范：

- 内边距：`15 px × 14 px`。
- 标题使用 `13 px` 粗体。
- 操作说明使用短行，按“按键 + 动作”排列。
- 本地统计放在卡片底部，并使用顶部细分隔线。
- 不显示完整操作历史，只显示游玩、完成、最佳和最长连胜等聚合数据。

## 4.5 控制栏

对象名：

- `gameControlBar`
- `startButton`
- `pauseButton`
- `restartButton`
- `undoButton`
- `holdButton`
- `soundToggle`

规范：

- 内边距：水平 `12 px`，垂直 `9 px`。
- 按钮间距：`8 px`。
- 主操作使用实色按钮，次要操作使用浅色表面和细边框。
- 准备状态显示“开始游戏”。
- 开始后隐藏重复的开始按钮，显示“暂停”和“重新开始”。
- 暂停后按钮文案改为“继续”。
- 游戏专用操作放在暂停和重新开始附近。
- 背景音乐开关位于最右侧。

## 5. 游戏舞台规范

游戏舞台由 `GameCanvas` 提供。

### 5.1 基础外观

- 对象名：`gameSurface`
- 最小尺寸：`280 × 280 px`
- 舞台圆角：`16 px`
- 内容内边距：`14 px`
- 默认边框：主题网格色，`1 px`
- 获得键盘焦点后：游戏强调色，`2 px`
- 开启抗锯齿、文字抗锯齿和平滑图像变换

### 5.2 键盘焦点

- 舞台必须使用 `Qt::StrongFocus`。
- 鼠标点击舞台后应恢复键盘控制。
- 焦点只通过边框变化提示，不使用闪烁或大面积高亮。
- 页面打开或重新开始后，焦点回到主游戏输入控件或舞台。

### 5.3 状态遮罩

暂停、胜利、失败和和棋使用半透明深色遮罩：

```text
┌────────────────────┐
│                    │
│       已暂停       │
│   按 Space 继续    │
│                    │
└────────────────────┘
```

规范：

- 遮罩覆盖完整舞台，不改变底层棋盘状态。
- 标题字号约 `22 pt`，白色粗体。
- 辅助提示字号约 `11 pt`，使用半透明白色。
- 淡入时长：`160 ms`。
- 缓动曲线：`OutCubic`。
- 动画只能改变显示，不得延迟暂停或终局状态切换。

## 6. 颜色系统

## 6.1 游戏强调色

| 游戏 | `gameId` | 主强调色 | 视觉含义 |
|---|---|---:|---|
| 猜数字 | `guess-number` | `#D89A22` | 推理、温暖、奖励 |
| 2048 | `game-2048` | `#E97835` | 合并、进展、成就 |
| 贪吃蛇 | `snake` | `#2E9B63` | 生长、活力、清晰 |
| 俄罗斯方块 | `tetris` | `#3977D5` | 节奏、空间、秩序 |
| 五子棋 | `gomoku` | `#A6533F` | 木质、沉稳、对弈 |

未知游戏默认使用应用主色 `#665CF2`。

### 6.2 主题派生

`GameVisualTheme` 必须根据当前 `QPalette` 生成：

- `accent`：游戏主色
- `accentStrong`：焦点、重要轮廓和高价值状态
- `accentSoft`：范围卡、弱背景和辅助区域
- `canvas`：舞台表面
- `board`：棋盘底色
- `grid`：网格和边框
- `text`：主要文字
- `muted`：说明和次要文字
- `overlay`：状态遮罩

深色主题判定标准：`QPalette::Window` 亮度小于 `128`。

### 6.3 对比度

- 不允许所有数字块固定使用同一种前景色。
- 数字和背景的组合必须通过 `readableTextColor()` 或同等明度判断。
- 网格线应弱于棋子、蛇身和方块。
- 红、绿等状态不能作为唯一信息，必须同时提供文字或形状。

## 7. 间距、圆角与字体

### 7.1 间距层级

统一使用以下间距：

| 层级 | 数值 | 用途 |
|---|---:|---|
| XS | `2 px` | 指标标题与数值 |
| S | `8 px` | 按钮、选项和局部控件 |
| M | `10–12 px` | 卡片与页面纵向间距 |
| L | `14–16 px` | 舞台、说明卡和主要内容块 |
| XL | `24 px` 以上 | 特殊视觉留白，谨慎使用 |

### 7.2 圆角

- 游戏舞台：`16 px`
- 状态、指标、说明和控制卡：`12 px`
- 按钮：`8 px`
- 配置下拉框：`7 px`
- 游戏内方块圆角按单元格尺寸动态计算

### 7.3 字体层级

| 内容 | 建议字号 | 字重 |
|---|---:|---|
| 状态值 | `15 px` | 700 |
| 指标值 | `18 px` | 700 |
| 说明标题 | `13 px` | 700 |
| 卡片小标题 | `11 px` | 常规 |
| 遮罩标题 | `22 pt` | 700 |
| 遮罩提示 | `11 pt` | 常规 |

游戏内数字必须根据位数和单元格大小自适应，不能依赖固定字号。

## 8. 棋盘几何规范

所有棋盘尺寸和鼠标命中必须复用 `board_geometry.h`，不能在绘制和点击处理中分别计算。

### 8.1 单元格棋盘

适用于：

- 2048
- 贪吃蛇
- 俄罗斯方块

使用 `makeCellGrid()` 计算：

- 棋盘矩形
- 行列数
- 单元格尺寸
- 单元格矩形和中心点

棋盘尺寸必须是单元格尺寸的整数倍，避免边缘出现 1–3 px 的残余区域。

### 8.2 交叉点棋盘

适用于五子棋。使用 `makeIntersectionGrid()` 统一计算：

- 棋盘矩形
- 左上交叉点
- 交叉点间距
- 坐标到棋盘点的命中结果

鼠标命中容差不能超过半个交叉点间距，棋盘外点击必须被拒绝。

## 9. 五款游戏的专属规范

## 9.1 猜数字

### 视觉重点

- 使用琥珀色。
- 画布中央显示“当前有效范围”。
- 使用水平范围条表达上下界收缩。
- 最近猜测显示数字、高低方向和冷热程度。
- 成功后显示尝试次数和得分。

### 控件

- 模式：经典、限次挑战。
- 范围：1–100、1–500、1–1000。
- 主输入只允许有效整数。
- 未开始、暂停或结束时禁止提交。

### 操作

- `Enter`：提交猜测
- `Space`：暂停或继续
- `R`：重新开始

## 9.2 2048

### 视觉重点

- 棋盘和数字块均使用圆角。
- 2、4、8 至 2048 使用稳定的离散色阶。
- 数字字号随位数自适应。
- 空单元格使用弱背景，不显示文字。
- 明确提示：每次有效移动后会新增一个 2 或 4。

### 控件

- 模式：经典、步数挑战。
- 每局允许一次“撤销一步”。
- 当前指标显示分数、移动次数和连击。

### 操作

- 方向键 / `WASD`：移动
- `Space`：暂停或继续
- `R`：重新开始

## 9.3 贪吃蛇

### 视觉重点

- 使用绿色。
- 蛇头使用更深或更亮的强调色，并显示方向眼睛。
- 蛇身使用统一圆角段。
- 普通食物使用红色，奖励食物使用黄色和加号。
- 障碍使用中性灰色，不能与蛇身混淆。
- 网格保持低对比度。

### 控件

- 模式：经典、穿墙、障碍。
- 当前指标显示分数、等级和连续进食倍率。
- 每 50 分提升一级并增加速度。

### 操作

- 方向键 / `WASD`：转向
- `Space`：暂停或继续
- `R`：重新开始

## 9.4 俄罗斯方块

### 视觉重点

- 使用蓝色工作台强调色。
- 七种方块使用固定颜色，不随主题改变色相。
- 活动方块、锁定方块和幽灵落点使用不同实虚层级。
- 宽画布右侧显示“暂存”和三个后续方块。
- 棋盘始终保持 `10 × 20` 比例。

### 方块颜色

| 方块 | 颜色 |
|---|---:|
| I | `#36C5F0` |
| O | `#F3C846` |
| T | `#A96DE0` |
| L | `#F08A3C` |
| J | `#477DE5` |
| S | `#52B96B` |
| Z | `#E75A67` |

### 操作

- `←` / `→` 或 `A` / `D`：移动
- `↑` 或 `W`：旋转
- `↓` 或 `S`：软降
- `Enter`：硬降
- `C`：暂存或交换方块
- `Space`：暂停或继续
- `R`：重新开始

## 9.5 五子棋

### 视觉重点

- 使用暖木色棋盘。
- 显示标准星位。
- 黑白棋子具有轻微阴影和高光，但不过度拟物。
- 最后一步使用红色小圆环。
- 获胜后使用黄色线段连接完整获胜序列。
- 键盘光标使用游戏强调色圆环。

### 控件

- 模式：本地双人、简单 AI、普通 AI。
- 人机模式可以选择执黑或执白。
- 本地双人撤销一步，人机模式撤销双方各一步。
- AI 计算期间显示“电脑思考中…”。

### 操作

- 鼠标：点击交叉点落子
- 方向键 / `WASD`：移动键盘光标
- `Enter`：落子
- `Space`：暂停或继续
- `R`：重新开始

## 10. 状态与文案

统一状态集合：

- 准备开始
- 游戏中 / 对局中
- 已暂停
- 目标完成 / 胜利
- 游戏结束 / 挑战失败
- 和棋
- 电脑思考中

### 10.1 文案原则

- 状态文案尽量控制在一行。
- 错误和终局文案说明下一步操作。
- 不使用只有开发者能理解的内部状态名。
- 遮罩提示优先使用快捷键，例如“按 R 再来一局”。
- 目标文案必须描述可验证条件，例如“80 步内合成 512”。

## 11. 动效与声音

### 11.1 动效

- 状态遮罩淡入：`160 ms`。
- 后续方块、合并、落子等短反馈建议控制在 `120–180 ms`。
- 不使用持续闪烁。
- 动画不能修改游戏规则状态，也不能阻塞输入线程。

### 11.2 背景音乐

- 所有游戏共享单例 `GameAudioController`。
- 同一时刻只能有一个游戏页面播放音乐。
- 进入游戏页时播放，离开时停止。
- 应用进入后台时暂停，恢复后按页面状态继续。
- `soundToggle` 当前表示“背景音乐”。
- 默认音量为 `16%`。
- 音乐来源、许可证和哈希见 `resources/audio/README.md`。
- 禁止使用系统报警音作为游戏反馈。

## 12. 浅色与深色主题

- 游戏页面不能设置独立于应用的固定整体样式表。
- 根游戏 QWidget 的 `styleSheet()` 应保持为空。
- 公共卡片样式由 `themeStyleSheet()` 和对象名控制。
- 自绘内容通过 `GameVisualTheme` 读取当前调色板。
- 深色主题中可以提高强调色亮度，但不能改变游戏的主色相。
- 五子棋木色棋盘可以单独使用深浅两套稳定颜色。

## 13. 可访问性

每个新增游戏必须满足：

- 游戏舞台具有非空 `accessibleName` 和准确的 `accessibleDescription`。
- 所有按钮具有工具提示、辅助名称和辅助描述。
- 键盘可以完成主要游戏流程。
- 暂停按钮必须始终可发现。
- 不能只用颜色表达当前玩家、错误、胜负或奖励。
- AI 思考、暂停和终局状态必须同步到 `gameStatus`。
- 新增控件应使用稳定对象名，便于辅助技术和自动测试定位。

必须保留的公共对象名：

```text
gameSurface
gameStatus
scoreLabel
highScoreLabel
startButton
pauseButton
restartButton
soundToggle
gameConfigBar
gameGoal
gameInstructions
gameStats
```

## 14. 响应式与窗口适配

- 默认设计基准为主窗口 `1000 × 680 px`，左侧导航约 `220–230 px`。
- 游戏工作区优先压缩说明栏，再压缩舞台外围留白。
- 舞台最小尺寸保持 `280 × 280 px`。
- 窄窗口下，俄罗斯方块可以隐藏画布内的暂存/预览区，但核心棋盘必须完整。
- 文字允许换行时，应保持按钮和棋盘位置稳定。
- 不允许通过绝对像素坐标放置页面级控件。

## 15. 实现边界

### 15.1 UI 层负责

- 布局和绘制
- 状态文字与遮罩
- 键盘和鼠标事件映射
- 轻量动画
- 背景音乐生命周期
- 本地统计展示

### 15.2 游戏逻辑层负责

- 移动和碰撞规则
- 计分、连击和等级
- 胜负与和棋判定
- 随机生成规则
- 撤销、悔棋和方块暂存状态
- AI 选点

UI 不得在 `paintEvent()` 中修改规则状态。

## 16. 新增小游戏检查清单

### 结构

- [ ] 通过 `createGamePage()` 创建统一页面。
- [ ] 设置稳定、唯一的 `gameId`。
- [ ] 使用状态卡、指标卡、配置栏、工作区和控制栏。
- [ ] 操作说明和本地统计完整。

### 视觉

- [ ] 为游戏选择一个低饱和强调色。
